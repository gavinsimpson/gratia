Subject: scasm() silently ignores marginal shape requests in ti() and t2()

Hi Simon,

In mgcv 1.9-4, scasm() accepts increasing marginal constraints in ti() and
t2() without a warning, but stores no inequalities and can fit a decrease.
Here is a t2() example:

library("mgcv")
set.seed(12)
d <- data.frame(x = runif(160), z = runif(160))
d$y <- -d$x - d$z + rnorm(160, sd = 0.01)
m <- scasm(y ~ t2(x, z, bs = c("sc", "sc"),
  xt = list("m+", "m+"), k = c(6, 6)), data = d)
nrow(m$Ain) # 0
diff(predict(m, data.frame(x = c(0.25, 0.75), z = 0.5))) # about -0.50

The tensor constructor explicitly excludes ti() when propagating marginal
inequalities, and the t2() constructor does not propagate them. I take this
to be unsupported fitting behavior, rather than evidence that either
constructor should use the te() implementation. Could these specifications
give a warning or error, and could the documentation state which tensor
types support marginal shape constraints? The current B-spline help says
that constraints can be used in tensor product terms without that distinction.

I also inspected the same constructor behavior in development source
labelled 1.9-5 on 16 October 2026. I have not run the complete development build.
